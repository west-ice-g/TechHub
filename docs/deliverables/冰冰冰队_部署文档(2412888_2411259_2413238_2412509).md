# 部署文档

## 1. 部署方案概览

TechHub 提供两种部署方式：

| 方案 | 适用场景 | 优点 | 入口 |
| --- | --- | --- | --- |
| 方案 A：Docker Compose | 全新服务器、课程答辩、快速复现 | PHP/Apache/MySQL 一次编排，数据库和迁移自动初始化 | `docker-compose.yml` + `deploy.sh` |
| 方案 B：本地 PHP + MySQL + Apache | 已有服务器、不能安装 Docker、传统课程环境 | 组件可控，便于逐项排查 | 手工安装 PHP、MySQL、Apache |

**推荐使用方案 A。** 方案 A 已提供完整的 Compose 编排、MySQL 初始化挂载、上传目录持久化、管理员首次密码初始化和一条命令启动/停止流程。

两种方案都要求：

- Web 根目录指向项目的 `public/`；
- `.env` 不提交 Git，不放入 Web 根；
- 数据库密码不使用示例值；
- 上传目录禁止执行脚本；
- 生产环境关闭 `APP_DEBUG`。

## 2. 方案 A：Docker Compose

### 2.1 Docker 文件清单

| 文件 | 作用 |
| --- | --- |
| `Dockerfile` | 构建 PHP 8.2 + Apache 运行镜像，安装 PDO MySQL、mbstring，启用 rewrite/headers |
| `docker-compose.yml` | 编排 `app` 和 `db` 两个服务，配置网络、端口、健康检查和卷 |
| `.env.example` | 环境变量模板；复制为 `.env` 后填写密码 |
| `deploy.sh` | 构建、启动、等待数据库、迁移、管理员初始化、备份和停止 |
| `docker/apache/techhub.conf` | Apache DocumentRoot、AllowOverride、上传目录禁脚本 |
| `docker/php.ini` | 上传大小、内存、时区和 Session 安全参数 |
| `docker/entrypoint.sh` | 创建并授权运行时目录 |
| `docker/init-admin.php` | 按环境变量设置首次管理员密码，不输出明文 |
| `.dockerignore` | 排除 `.env`、Git、文档、运行数据和上传文件 |

### 2.2 前置条件

安装：

- Docker Engine 24+ 或 Docker Desktop；
- Docker Compose v2（`docker compose` 命令）；
- 能拉取 `php:8.2-apache` 和 `mysql:8.0` 镜像；
- 至少 1GB 可用内存和 2GB 磁盘。

验证：

```bash
docker --version
docker compose version
```

### 2.3 配置环境变量

在项目根目录：

```bash
cp .env.example .env
```

编辑 `.env`，至少修改以下值：

```dotenv
APP_URL=http://localhost:8090
APP_PORT=8090

MYSQL_DATABASE=techhub
MYSQL_USER=techhub_app

MYSQL_PASSWORD=替换为应用强密码
MYSQL_ROOT_PASSWORD=替换为数据库管理员强密码

DB_PASSWORD=替换为应用强密码
INITIAL_ADMIN_PASSWORD=替换为管理员首次登录强密码
INITIAL_EDITOR_PASSWORD=替换为编辑账号密码
```

配置要求：

1. `DB_PASSWORD` 与 `MYSQL_PASSWORD` 保持一致；`deploy.sh` 会检查。
2. `MYSQL_DATABASE` 保持 `techhub`，因为 `data/install.sql` 和迁移文件使用该库名；如需改名必须同步修改 SQL。
3. `INITIAL_ADMIN_PASSWORD` 至少 8 个字符，不能使用 `change-me` 示例值。
4. `.env` 权限建议 `600`，禁止提交 Git。
5. Docker 内部应用连接数据库使用 `DB_HOST=db`、`DB_PORT=3306`，不要改为宿主机的 `127.0.0.1`。

### 2.4 一条命令启动

```bash
chmod +x deploy.sh
./deploy.sh up
```

如果使用非默认环境文件，可以指定 `ENV_FILE`：

```bash
ENV_FILE=.env.production ./deploy.sh up
```

`deploy.sh up` 会依次：

1. 检查 Docker Compose 和 `.env`；
2. 创建持久化目录；
3. 构建 PHP/Apache 镜像；
4. 启动 MySQL 和 app；
5. 等待 MySQL 健康；
6. 执行可重复迁移；
7. 按 `.env` 设置首次管理员密码；
8. 输出访问地址。

首次启动时 MySQL 容器会自动执行：

```text
docker-entrypoint-initdb.d/01-install.sql
docker-entrypoint-initdb.d/02-frontend.sql
docker-entrypoint-initdb.d/03-admin.sql
docker-entrypoint-initdb.d/04-admin-demo-dates.sql
```

其中 `01-install.sql` 创建数据库、17 张表、21 个外键、角色权限和示例数据；后续三个脚本执行结构迁移和示例日期迁移。

### 2.5 访问

默认：

```text
前台：http://localhost:8090
后台：http://localhost:8090/admin/login
```

如修改 `APP_PORT`，前台地址相应变化。正式服务器应通过 Nginx/Apache 反向代理或直接映射 80/443，并配置 HTTPS。

### 2.6 数据持久化

| 数据 | 保存方式 | 说明 |
| --- | --- | --- |
| MySQL 数据 | 命名卷 `techhub_db_data` | `docker compose down` 不删除；`down -v` 会删除 |
| 团队作业 | `data/team/` 绑定挂载 | 宿主机可直接备份 |
| 个人作业 | `data/personal/` 绑定挂载 | 宿主机可直接备份 |
| 通用资源 | `data/resources/` 绑定挂载 | 宿主机可直接备份 |
| 用户上传图片 | `public/uploads/` 绑定挂载 | Nginx/Apache 禁止执行脚本 |
| Session | 命名卷 `techhub_sessions` | 避免宿主机旧 Session 文件造成 strict mode 冲突 |
| 日志 | `storage/` 绑定挂载 | `storage/logs` 可写 |
| 代码/图片/SQL | 构建进 app 镜像 | 更新代码后需要重新 build |

持久化目录必须由 Docker 容器写权限。`entrypoint.sh` 会创建并授权运行目录；Session 使用独立命名卷，避免宿主机旧 Session 文件与容器用户 UID 不一致。

### 2.7 服务管理

```bash
./deploy.sh start       # 启动已有容器
./deploy.sh stop        # 停止容器
./deploy.sh restart     # 重启容器
./deploy.sh down        # 停止并移除容器，保留数据库卷和文件
./deploy.sh logs        # 跟踪日志
./deploy.sh status      # 查看状态
```

不要随意执行：

```bash
docker compose down -v
```

该命令会删除数据库卷，导致数据不可恢复。只有明确要清空重装时才使用。

### 2.8 管理员初始化与重置

`deploy.sh up` 会调用：

```bash
docker compose exec -T app php /var/www/html/docker/init-admin.php
```

脚本同时初始化 `INITIAL_ADMIN_PASSWORD` 和（如果已配置）`INITIAL_EDITOR_PASSWORD`。

脚本行为：

- 从环境变量读取 `INITIAL_ADMIN_USERNAME` 和 `INITIAL_ADMIN_PASSWORD`；
- 校验密码长度和不使用示例占位符；
- 首次部署（管理员 `last_login_at` 为空）时写入 `password_hash`；
- 管理员已登录过后默认跳过，避免每次重启重置密码；
- 需要强制重置时：

```bash
# 修改 .env 中 INITIAL_ADMIN_PASSWORD 和 RESET_ADMIN_PASSWORD=1
./deploy.sh init-admin
```

完成后建议改回 `RESET_ADMIN_PASSWORD=0`。

### 2.9 迁移与升级

代码升级后：

```bash
./deploy.sh up
```

该命令会重新构建镜像，并再次执行三个迁移脚本。迁移脚本可重复运行；如果新增了迁移文件，应把它们加入 `deploy.sh` 的 `run_migrations()` 和 `docker-compose.yml` 的 MySQL initdb 挂载。

仅执行迁移、不重建容器：

```bash
./deploy.sh migrate
```

### 2.10 备份

```bash
./deploy.sh backup
```

生成：

```text
backups/techhub-YYYYMMDD-HHMMSS.sql
backups/files-YYYYMMDD-HHMMSS.tar.gz
```

数据库备份使用容器内 root 账号，文件备份包含 `data/team`、`data/personal`、`data/resources` 和 `public/uploads`。备份目录不得放入公开 Web 路径。

### 2.11 查看日志

```bash
./deploy.sh logs
```

或：

```bash
docker compose logs -f app
docker compose logs -f db
```

应用日志同样保存在 `storage/logs/`。

### 2.12 Docker 故障排查

| 现象 | 排查 |
| --- | --- |
| 构建失败 | 检查 Docker 网络能否访问镜像仓库 |
| app 启动失败 | `docker compose logs app`；检查 Apache 配置和目录权限 |
| app 健康检查失败 | 检查 app 是否能连接 `db`，数据库是否完成初始化 |
| db 一直 unhealthy | 检查 MySQL 密码是否包含特殊字符并正确写入 `.env` |
| 访问 500 | 查看 `storage/logs/app-*.log` 和容器日志 |
| 页面 404 | 确认 `mod_rewrite` 启用、DocumentRoot 指向 `/var/www/html/public` |
| 上传失败 | 检查 `public/uploads` 挂载和容器内 `www-data` 权限 |
| 数据库数据消失 | 是否执行了 `down -v`；命名卷是否被删除 |
| 修改 SQL 后未生效 | MySQL initdb 只在空数据卷首次运行；使用 `./deploy.sh migrate` 或清空开发卷 |

## 3. 方案 B：本地 PHP + MySQL + Apache

### 3.1 环境要求

| 组件 | 要求 |
| --- | --- |
| 操作系统 | Linux/Windows |
| PHP | 8.2+ |
| MySQL | 8.0+ |
| Apache | 2.4+，启用 rewrite/FastCGI/Fcgid |
| PHP 扩展 | PDO、pdo_mysql、fileinfo、mbstring、openssl、curl |

### 3.2 安装 PHP

Linux（Debian/Ubuntu 示例）：

```bash
sudo apt update
sudo apt install -y php8.2-cli php8.2-fpm php8.2-mysql \
  php8.2-mbstring php8.2-xml php8.2-curl php8.2-zip
php -v
php -m
```

Windows：

1. 下载 PHP 8.2+ Windows ZIP；
2. 解压到无中文/空格目录；
3. 复制 `php.ini-development` 为 `php.ini`；
4. 设置 `extension_dir`，启用 `pdo_mysql`、`fileinfo`、`mbstring`、`openssl`、`curl`；
5. 设置 `date.timezone = Asia/Shanghai`；
6. 执行 `php -v`、`php -m` 验证。

上传限制：

```ini
upload_max_filesize = 20M
post_max_size = 21M
```

### 3.3 安装 MySQL 并初始化

安装 MySQL 8.0+ 后，使用管理员账号登录，创建数据库和最小权限业务账号：

```sql
CREATE DATABASE `techhub`
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_0900_ai_ci;

CREATE USER 'techhub_app'@'127.0.0.1'
  IDENTIFIED BY '替换为应用强密码';

GRANT SELECT, INSERT, UPDATE, DELETE
  ON `techhub`.* TO 'techhub_app'@'127.0.0.1';

FLUSH PRIVILEGES;
```

如果应用通过 `localhost` 连接，请按实际 Host 创建账号。应用账号没有建表和迁移权限，建表和迁移使用管理员账号执行。

导入：

```bash
mysql -u root -p --default-character-set=utf8mb4 < data/install.sql
mysql -u root -p techhub < data/migrations/2026-11-25_frontend.sql
mysql -u root -p techhub < data/migrations/2026-11-25_admin.sql
mysql -u root -p techhub < data/migrations/2026-11-25_admin_demo_dates.sql
```

验证：

```sql
USE techhub;
SHOW TABLES;
SELECT COUNT(*) FROM information_schema.tables
WHERE table_schema = 'techhub' AND table_type = 'BASE TABLE';
SELECT COUNT(*) FROM information_schema.referential_constraints
WHERE constraint_schema = 'techhub';
SHOW COLUMNS FROM activity_logs LIKE 'result';
```

预期：17 张表、21 个外键、`result` 字段存在。

### 3.4 配置 `.env`

复制模板：

```bash
cp .env.example .env
```

本地部署时修改：

```dotenv
APP_ENV=production
APP_DEBUG=false
APP_URL=http://your-host:8090
APP_PORT=8090

DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=techhub
DB_USERNAME=techhub_app
DB_PASSWORD=替换为与 MySQL 应用账号一致的密码
DB_CHARSET=utf8mb4
```

如果 PHP 直接运行在宿主机，`DB_HOST` 不应使用 Docker 网络的 `db`。

### 3.5 Apache 配置

Linux + PHP-FPM：

```bash
sudo a2enmod rewrite headers proxy_fcgi setenvif
sudo a2enconf php8.2-fpm
sudo systemctl reload apache2
```

虚拟主机：

```apache
<VirtualHost *:80>
    ServerName techhub.example.com
    DocumentRoot /var/www/techhub/public

    <FilesMatch \.php$>
        SetHandler "proxy:unix:/run/php/php8.2-fpm.sock|fcgi://localhost"
    </FilesMatch>

    <Directory /var/www/techhub/public>
        Options -Indexes +FollowSymLinks
        AllowOverride All
        Require all granted
    </Directory>

    ErrorLog ${APACHE_LOG_DIR}/techhub-error.log
    CustomLog ${APACHE_LOG_DIR}/techhub-access.log combined
</VirtualHost>
```

Windows + Fcgid 示例：

```apache
LoadModule fcgid_module modules/mod_fcgid.so
LoadModule rewrite_module modules/mod_rewrite.so

<VirtualHost *:80>
    ServerName techhub.example.com
    DocumentRoot "C:/www/techhub/public"

    FcgidInitialEnv PHPRC "C:/php/8.2"
    FcgidWrapper "C:/php/8.2/php-cgi.exe" .php
    AddHandler fcgid-script .php

    <Directory "C:/www/techhub/public">
        Options -Indexes +FollowSymLinks
        AllowOverride All
        Require all granted
    </Directory>
</VirtualHost>
```

配置后执行：

```bash
apachectl configtest
sudo systemctl reload apache2
```

### 3.6 Nginx 配置（可选）

```nginx
server {
    listen 80;
    server_name techhub.example.com;
    root /var/www/techhub/public;
    index index.php;
    client_max_body_size 21m;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location ~ \.php$ {
        include fastcgi_params;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        fastcgi_pass unix:/run/php/php8.2-fpm.sock;
    }

    location ~ /\.(?!well-known) {
        deny all;
    }

    location ^~ /uploads/ {
        location ~ \.(php|phtml|phar)$ {
            deny all;
        }
    }
}
```

### 3.7 文件权限

需要可写：

```text
storage/sessions
storage/logs
public/uploads
data/team
data/personal
data/resources
```

Linux 示例：

```bash
sudo chown -R www-data:www-data storage public/uploads data/team data/personal data/resources
sudo find storage public/uploads data/team data/personal data/resources -type d -exec chmod 775 {} \;
sudo chmod 640 .env
```

Windows 下给 Apache/IIS 服务账号授予对应目录的修改权限。不要给上传目录执行脚本的权限。

### 3.8 启动本地 PHP 服务器（开发用）

```bash
php -S 127.0.0.1:8090 -t public public/router.php
```

生产环境不要使用 PHP 内置服务器。

### 3.9 子目录与 HTTPS

子目录部署设置：

```dotenv
APP_BASE_PATH=/techhub
```

并让 Web 服务器把 `/techhub` 映射到项目 `public/`。生产环境应配置 HTTPS，80 端口重定向到 443。

- `storage/logs` 和 `.env` 不可公开访问。

## 5. 备份与还原

### 5.1 Docker 方案

```bash
./deploy.sh backup
```

数据库在命名卷 `techhub_db_data` 中，作业文件和上传图片在宿主机绑定目录中。

恢复：

```bash
# 停止应用，保留数据库卷
./deploy.sh stop

# 重建容器（不清空卷）
./deploy.sh up

# 恢复数据库（示例）
docker compose exec -T db sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" "$MYSQL_DATABASE"' \
  < backups/techhub-YYYYMMDD-HHMMSS.sql

# 解压文件
tar -xzf backups/files-YYYYMMDD-HHMMSS.tar.gz
```

### 5.2 本地方案

```bash
mysqldump -u root -p --default-character-set=utf8mb4 \
  --routines --triggers techhub > techhub-backup.sql
tar -czf files-backup.tar.gz data/team data/personal data/resources public/uploads
```

恢复时先创建空库，再导入备份、恢复文件、重新配置 `.env`，最后执行三套测试。

### 7.1 一个实际兼容性修复

CSRF 失败原本返回非标准状态码 `419`。本机 PHP 内置服务器可以返回该状态，但 Apache 会把它映射成 500。因此项目已统一改为返回标准 `403`，并同步更新测试与文档，保证 Docker/Apache 环境下行为一致。

### 7.2 说明

- Docker 冷启动验证使用了独立的测试环境变量文件，测试密码不写入仓库；
- 上传文件、Session 卷、数据库卷和持久化目录均按本文档设计；
- 如果目标机器的 Docker 网络无法访问镜像仓库，应先配置 Docker 镜像代理或镜像源，再执行 `./deploy.sh up`；
- 失败时查看 `docker compose logs db` 和 `docker compose logs app`，不要把“配置已写”表述为“部署已通过”。
